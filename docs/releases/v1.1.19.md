# stack-single 1.1.19

Pins only: tokenfuse moves to `v1.6.0`.

## What moves

- **tokenfuse `v1.5.0` -> `v1.6.0`**: `tokenfuse-control-plane`, the gateway,
  `focus-export` and `tokenfuse-mcp-broker`. The tag is v1.6.0 on tokenfuse
  `f342412` and carries tokenfuse#356 and #358.
  - **The MCP broker speaks streamable HTTP to its upstream** (tokenfuse#358,
    invariant 76).
    - It sends `Accept: application/json, text/event-stream`.
    - It reads an event-stream reply, so an MCP Python SDK server behind
      `TOKENFUSE_MCP_UPSTREAMS` no longer answers 406 or a reply the broker
      cannot parse.
    - The typryx upstream this launcher wires by default answered JSON before
      and still does.
  - **The Cloud serves `GET /v1/run-spend`** (tokenfuse#356, invariant 75).
    - It answers only a key bound to a site, and only about that site's runs.
    - A remote site's gateway uses it to seed its runs' spend after a restart,
      through a stack-k8s hub entry.
    - On a single box the gateway's Cloud key is bound to no site, so the
      route answers 403 and the gateway seeds from `GET /v1/runs` as before.
      Nothing changes on a single box.

No other pin moves.

## Measured

- **tokenfuse#356** was measured locally with release binaries: a restarted
  site gateway got 402 where v1.5.0's got 200, at the same Cloud state and
  budget. That run was not on a single box.
- **tokenfuse#358** was measured in its own PR against MCP Python SDK 1.30.0
  and 2.3.0 servers.

## Not proven

- **A single-box install with this pin.** None was run. `install.sh` was not
  re-run here.
