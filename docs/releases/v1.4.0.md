# stack-single 1.4.0 (a minor release: it was planned as 1.3.2 and renamed, because it turns the record plane on by default and removes the containers of profiles that are off, both of which an operator sees)

Seven defects were measured on a forge upgrade from 1.1.35 to 1.3.1 on 2026-10-19, and one on a fresh 1.3.1 box (gcp2). Each has a gate, teeth cases and a feature file in this release. The static allow-lists a 1.3.1 re-run widened are cut back on this run.

## Upgrade first

1. **The record plane now starts on every box that does not set `WITH_RECORD=0`.** It is a core control and runs the pinned `trailryx-node` image, with no build. A box that must stay without it runs `WITH_RECORD=0 ./install.sh`, and that run stops and removes `record-seal` if it was running.
2. **Containers of profiles this run does not name are removed.** On the next run, for example, the FinOps console (profile `finops`) and, when `TYPED_MODE` is off, the typed plane's broker and typryx are stopped and removed by name. Nothing else is touched. Start one again by naming its profile, as the README describes.
3. **A box given its own `CLIENT_KEYS_FILE` must add its broker's key to that file.** Agent tokens are on by default, and the MCP broker needs a key of its own. Add a line `<secret>:broker` (the secret, a colon, then the word `broker`), bound in your identity map to `agent://<trust domain>/agents/*`. Or run `ADD_BROKER_KEY=1 ./install.sh`, and the installer mints the secret and appends that line, keeping the file's mode, once the identity map binds `broker`. Without one of those the installer refuses before it writes anything. The README said `broker:<secret>` before this release; that form was never read.
4. **A box that ran 1.3.1 more than once had the agents' and the fire drills' keys put on its static allow-lists.** This run removes both ids from the gateway's list and the broker's list, unless you name them in `STATIC_KEY_IDS`. The closing report says which ids it removed. To keep the agents' key on the static list while you move the agents to tokens, run `STATIC_KEY_IDS=agents ./install.sh` (the key must be one the box holds; the installer refuses a name it does not hold). Until an agent uses a token, a call it makes with a removed static key is refused `401 agent_token_required`.
5. Then re-run `./install.sh`. Nothing else needs doing: the volumes of an upgraded box are re-owned to their services' users on every run.

## What changed

- **Every read-write volume of a non-root service is re-owned to its uid, recursively, on every run** (CLAUDE.md invariant 49). The gateway's retained-reservation journal and typryx's ledger were left with the uid of an earlier release, so the gateway stopped and the typed plane could not write. The one-shots now `chown -R` each volume.
- **A compose profile this run does not name has no container left behind** (invariant 50). The cleanup covers every profile the compose file defines, not two by hand. After the 1.1.35 to 1.3.1 upgrade the FinOps console still ran its 0.6.0 image.
- **The record plane is on by default** (invariant 51). `WITH_RECORD=1` no longer builds trailryx from source; only `BUILD_FROM_SOURCE=1` does.
- **The bus directory can be entered by others, but nothing is written in it by anyone but the setup script** (invariant 52). The FinOps console's stream was created correctly, but the directory above it did not let its uid in. Measured on a fresh 1.3.1 box as "permission denied" on open.
- **A re-run keeps exactly the static allow-list the last run wrote, and the installer's own agents and fire-drills keys are cut from a widened list** (invariant 53, amending 47). A second run no longer adds them; an upgrade removes them unless `STATIC_KEY_IDS` names them, and the closing report says so.
- **The broker's key line is `<secret>:broker` everywhere, and `ADD_BROKER_KEY=1` adds it** (invariant 48). The refusal names both ways out.

## Measured

- forge, 2026-10-19, upgrade 1.1.35 to 1.3.1: the broker line refusal (logs 19 to 31); the gateway's journal and typryx's ledger left with an earlier uid (logs 31 to 35); the FinOps console still on image v0.6.0 after the upgrade; the second install run widened the allow-list to the agents' and drills' keys.
- gcp2, 2026-10-19, a fresh 1.3.1 box: the FinOps console started with "permission denied" on open of its own stream (its logs 13b).
- The gates: `broker-key-is-the-keys-file-line.sh`, `volumes-are-reowned.sh`, `profiles-off-are-removed.sh`, `record-plane-is-on-by-default.sh`, `costcrew-can-reach-its-stream.sh`, and `agent-tokens-are-wired.sh` extended with a two-run section and a section for a `.env` that a 1.3.1 re-run widened. Each of those gates was run red on 1.3.1, before its fix, and failed for the stated reason. The new teeth cases ran against the fixed tree, where each planted fault goes red.

## Not measured

- A live run of this installer on forge or gcp2. The upgrade itself, and the record seal running on the box with trailryx 1.4.0, are not yet run for this release.
- The costcrew traversal fix was read from Unix permissions, not run in a container.
- A container kept on an on-profile whose pinned image changed: compose recreates a container whose configuration changed, and no gate measures it on a live stack.
- The DPoP door origins (`TODO(1.4.0, D13)` in `install.sh`): the gateway still accepts a proof for one origin only. The setting that lists them is not in any tokenfuse release this pin reads, and this release does not wait for it.
