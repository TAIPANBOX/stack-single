# stack-single 1.1.22

Pins only: tokenfuse moves to `v1.8.0`.

## What moves

- **tokenfuse `v1.7.0` -> `v1.8.0`**: `tokenfuse-control-plane`, the gateway,
  `focus-export` and `tokenfuse-mcp-broker`. The tag is v1.8.0 on tokenfuse
  `8023010`, published 2026-10-08 for amd64 and arm64 (index
  `sha256:61df27faf983c98e216427c67723dd23f88544382867fa2cd38bc444f236d40f`
  for `tokenfuse:v1.8.0`,
  `sha256:a956befcad7f1fbdc1573e47722d25b381f4a134164c3e38da9f826c9a041484`
  for `tokenfuse-control-plane:v1.8.0`, read with
  `docker buildx imagetools inspect`). TokenFuse's own notes:
  `docs/releases/v1.8.0.md` in that repository.
  - **The control plane files a call refused for identity under the
    credential that made it** (tokenfuse#373), as the FOCUS export has since
    v1.7.0, and counts every Breaker reason, `identity_mismatch` and
    `unit_budget_exceeded` included, as compliance evidence.
  - **A refused run reads as refused, and a fallback price is visible**
    (tokenfuse#375). The control plane's runs carry their refused calls, their
    latest decision and their fallback-priced calls; the gateway tells it the
    basis each admitted call was charged at.
  - **`GET /v1/price-book` on the gateway** (tokenfuse#374): which book it
    charges with, what a `TOKENFUSE_PRICE_BOOK` file replaced and added, and
    the model ids charged at the fallback. It sits behind the admin keys, so
    here it takes `GATEWAY_ADMIN` like `/v1/runs` and `/v1/policy-plane`.
  - **A call forwarded under identity warn mode is marked** (tokenfuse#377):
    a trace column, `identity_reason`, and a FOCUS column appended last,
    `x_identity_reason`. This launcher configures no client keys and no
    identity map for the gateway, so no identity check runs here and the
    column stays empty.

No other pin moves. `TOKENFUSE_IMAGE` and `TOKENFUSE_CLOUD_IMAGE` still
override the defaults. TokenFuse changed no Dockerfile and no
`components.json` entry between v1.7.0 and v1.8.0, so the binary paths
`compose.yaml` names are unchanged.

## Upgrading

- **Nothing to configure.** TokenFuse names no new setting. Every
  `TOKENFUSE_*` name `compose.yaml` hands the gateway, the control plane or
  the broker is still read at v1.8.0, and nothing frozen in TokenFuse's
  `compat/1.0.json` moves. Re-running `install.sh` pulls the new images;
  `.env` is not rewritten.
- **`focus-export`'s CSV files gain one column at the end**,
  `x_identity_reason`. A consumer that reads columns by name needs nothing.
  CostCrew's FOCUS reader reads by name and refuses only a missing column.
- **The control plane's saved state loads.** Figures folded before the
  upgrade keep their attribution; the new counts start at zero.

## Not proven

- **A single-box install with this pin.** None was run. `install.sh` was not
  re-run here.
- **The new figures through this stack.** No live model call was made here.
  TokenFuse's own notes say no live call to any provider, and no live control
  plane, was used for its release either; its changes are held by its tests.
