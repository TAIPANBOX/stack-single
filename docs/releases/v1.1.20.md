# stack-single 1.1.20

Pins only: tokenfuse moves to `v1.6.1`.

## What moves

- **tokenfuse `v1.6.0` -> `v1.6.1`**: `tokenfuse-control-plane`, the gateway,
  `focus-export` and `tokenfuse-mcp-broker`. The tag is v1.6.1 on tokenfuse
  `de9445a` and carries tokenfuse#360.
  - **The MCP broker keeps the session a stateful MCP server opens**
    (tokenfuse#360, invariant 77).
    - A server built on the MCP Python SDK runs stateful by default. Behind
      `TOKENFUSE_MCP_UPSTREAMS` it used to answer `initialize` and then
      `400 Missing session ID` to every later call. It now works through the
      broker.
    - The client receives the server's session id bound to that upstream and
      to the broker credential that opened it. Presented with another
      upstream or another credential, the id is refused with `404` and never
      forwarded.
    - A notification is answered `202` with no body.
    - The typryx upstream this launcher wires by default keeps no session, and
      nothing changes for it.

No other pin moves.

## Measured

tokenfuse#360 was measured in its own PR. The target was MCP Python SDK
1.30.0 and 2.3.0 servers in their default stateful mode, and the SDK's own
client listed and called a tool through the broker.

## Not proven

- **A single-box install with this pin.** None was run. `install.sh` was not
  re-run here.
