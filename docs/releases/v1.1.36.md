# stack-single 1.1.36

This release moves the image pins to the 2026-10-17 agent-security wave: every component
that wave shipped, signed in cosign's legacy `.sig` format, so the cluster admission policy
can read it. The installer changes in the same release close the compatibility conflicts
the wave's check found. Nothing new runs by default.

## Upgrade first

**1. Mail is sent over TLS, and you may need to name the mode.** heraldyx 0.8.0 uses STARTTLS
by default, and a server on port 465 selects implicit TLS by itself. A server that does not
offer STARTTLS is refused, and `plain` is allowed only for a loopback host. If your mail
server is a plain relay on this box, set `SMTP_TLS=plain` in `.env` before you start. The
installer asks for the mode after the server address on a first run. A value it does not read
is refused before anything is installed.

**2. Stream files are mode 0640, and each belongs to its writer.** agent-stack-go v2 creates a
stream file with mode 0640, and only in a directory its writer's account owns. This launcher
creates every bus stream beforehand, as its writer's uid, in `init-volumes`, so no writer has to
create one. An install from an earlier release already has them. To see them:

```bash
docker run --rm -v agent-stack_events:/vol busybox ls -ln /vol
```

Each `*.ndjson` should be mode `-rw-r-----`, owned by the uid of the plane that writes it, group
10001. Readers in the group can read them. Nothing on the bus is rewritten.

**3. vouchryx 0.6.0 refuses keyryx variables unless its signer is keyryx.** This launcher keeps
vouchryx's file signer, so nothing changes, and every keyryx variable reaches the container empty.
If you switch to keyryx signing by hand, set `VOUCHRYX_SIGNER=keyryx` and the keyryx variables
(`VOUCHRYX_KEYRYX_URL`, `VOUCHRYX_KEYRYX_CONSUMER`, `VOUCHRYX_KEYRYX_SOCKET` or
`VOUCHRYX_KEYRYX_CREDENTIAL_FILE`) in `.env`, and `VOUCHRYX_KEYRYX_ROOT_PIN` set to the kids of
keyryx's delegation root, which 0.6.0 requires. This launcher has not run keyryx signing.

**4. The demo issuer's line gets `|unbound`.** vouchryx 0.5.0 and later refuse a subject token
with no `cnf.jkt` unless its issuer's line ends in `|unbound`. The demo IdP's tokens carry none. A
rerun with `WITH_DELEGATION_DEMO_ISSUER=1` rewrites the demo line in `.env` from the old form to
the suffixed one, and changes no other line. An operator's own `VOUCHRYX_TRUSTED_ISSUERS` line is
never touched. If your identity provider issues unbound tokens on purpose, add `|unbound` to your
own line yourself. Do not add it if its tokens are bound.

**5. Agent tokens move to one https audience (boxes with `WITH_AGENT_TOKENS=1`).** The gateway and
the MCP broker now share `https://stack-single.<trust domain>` as their audience, in place of two
`http://` origins. tokenfuse 1.17.0 refuses an agent audience that is not an https URL, and one
agent token has to verify at both doors. tokenfuse 1.18.0 also refuses a broker that names a taint
gateway without a key file for it; the installer already writes that file, and the broker's key
is the `broker` client key. A rerun with `WITH_AGENT_TOKENS=1` writes the new values,
and compose recreates the gateway and the broker because their environment changed. A token minted for the old audience stops verifying, so
the enrolled agent must exchange its secret again, asking for `resource=https://stack-single.<trust domain>`
(RFC 8707; `audience=` also works). A request that names no audience is refused `audience_not_allowed`,
because vouchryx would then fall back to its own issuer, which the allow-list does not name. The agent's
DPoP proof to the gateway or the broker carries `ath`, the hash of the token (RFC 9449). Do the rerun in
one restart window.

Nothing is served at that audience, and it does not need to be. The consequence is that the
broker's protected-resource document names an https URL that no server answers. An MCP client
that finds the broker through that document cannot reach it. The agent in this stack gets its
token from vouchryx directly.

**6. Analyst ids in costcrew 0.8.0 and later are `agent://<host>/costcrew/<name>`.** This launcher
binds no analyst id to a gateway key, an identity map or a policy. If you did, rebind it to the
new form before the upgrade.

**7. The other pins change no configuration here.** agent-conform 2.0.1 keeps the
`watch-dir -every -out -state` flags this launcher passes, checked against its source at
v2.0.1, and its writer opens an existing stream rather than creating one. wardryx 2.2.1 changes
no behaviour. If this box switched approvals to keyryx while holds granted under the HMAC signer
were still pending, set `WARDRYX_APPROVAL_V2_UNTIL` in `.env` to an instant at least ten minutes
after that switch. Otherwise leave it unset.

`components.json`, and the installer's own vouchryx demo-key step carries the same digest.

## Not proven

- The new images have not been pulled, verified and started on a machine from this release.
  CI's install leg runs `install.sh` on a fresh Ubuntu runner, which is the first run of
  `cosign verify` against the legacy `.sig` form of these images.
- The mail paths against a real server. The TLS modes are tested in heraldyx and in this
  repository's gate on the values the installer writes, not against a live mail server.
- An enrolled agent exchanging a token and presenting it at both doors on the https audience.
- Whether the old `http://` audience's tokens stop verifying on a box that ran the previous
  pins. The release notes of tokenfuse 1.17.0 say so, and this release did not measure it.
