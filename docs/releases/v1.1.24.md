# stack-single 1.1.24

TokenFuse moves to `v1.9.0` and the console to `genaryx-console:v1.1.34`, the
two releases that make `WITH_CLOSURE=1` (invariant 26) work end to end.

## What moves

- **TokenFuse `v1.8.0` -> `v1.9.0`**: the gateway, the MCP broker, the
  `focus-export` job (`TOKENFUSE_IMAGE`) and the control plane
  (`TOKENFUSE_CLOUD_IMAGE`). Release notes:
  [tokenfuse v1.9.0](https://github.com/TAIPANBOX/tokenfuse/releases/tag/v1.9.0).
  - **A retained reservation survives a restart.** A call the provider may
    have billed but the gateway could not settle is journaled under
    `TOKENFUSE_DATA_DIR` (this launcher sets it) and put back at startup. A
    journal that exists and cannot be read stops the gateway (exit 2) instead
    of serving as if nothing were owed.
  - **It can be closed with evidence**, `POST /v1/retained/close` and
    `GET /v1/retained` behind the admin key, only when
    `TOKENFUSE_CLOSURE_SECRET` is set, which `WITH_CLOSURE=1 ./install.sh`
    does and a default install does not.
  - **An observed closure reaches the Cloud** the way a settled call does.
  - **The Cloud no longer accepts the fixed development key**, and
    `TOKENFUSE_CLOUD_ALLOW_DEVKEY` now stops it at start. This launcher never
    set it.
- **Console `v1.1.25` -> `v1.1.34`** (`CONSOLE_IMAGE`, the console and the
  `verdryx-drift` routine), built by stack-k8s tag v1.1.34 from genaryx
  `2317d80` (genaryx#91 to #105).
  - **`money_close_retained`**: an admin closes a retained reservation with
    evidence after a passkey assertion; the console mints the token the
    gateway verifies. On with `WITH_CLOSURE=1`.
  - **A refusal for identity is filed under the key that made the call**, not
    the agent it claimed, in the statistics, the incident centre, Agent 360,
    the delegation graph and Felyx's cost reads.
  - **Felyx counts a reasoning model's output the way the provider bills it.**

No other pin moves.

## Measured

On Docker Compose, 2026-10-12, the gateway, control plane and console wired
as this compose file wires them, with the published `tokenfuse:v1.9.0`,
`tokenfuse-control-plane:v1.9.0` and `genaryx-console:v1.1.34` and a stub
provider: 29 of 29 checks, twice from empty
([stack-k8s evidence/closure-verified.md](https://github.com/TAIPANBOX/stack-k8s/blob/main/evidence/closure-verified.md),
the harness beside it). A console closed a retained reservation with an
observed 4321 micro-USD: the gateway settled exactly that, released the
reservation, and the control plane counted it once; a second close was refused
`already_closed`. A no-charge closure settled nothing. A console holding a
different secret was refused by the gateway. After a gateway restart the one
open reservation was still retained and the closed ones were not. With
`GENARYX_WEB_REQUIRE_PASSKEY=1`, as this launcher sets, the close was refused
before it reached the gateway.

## Upgrading

- **Nothing to configure** for a box that does not close reservations.
- **To turn closing on**, run `WITH_CLOSURE=1 ./install.sh`. It mints the one
  secret into `.env` and `./closure/secret`; a re-run keeps it.

## Not proven

- **`install.sh` with these pins on Debian.** CI's install legs run it on
  Ubuntu; no box was upgraded by hand.
- **A closure against a live provider bill.** The run above used a stub
  provider.
- **The unit half.** No identity map was configured, so no unit reservation
  was retained or closed.
- **The passkey ceremony end to end.** The run used the console's documented
  no-passkey fallback for the close and showed the refusal with
  `GENARYX_WEB_REQUIRE_PASSKEY=1`, which this launcher sets; the ceremony
  itself is held by genaryx's router tests.
