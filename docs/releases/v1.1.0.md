# stack-single 1.1.0

Deployment two of three of the TAIPANBOX stack: one Debian or Ubuntu box, one
installer, one Compose file. A stack release is a pinned set with a date: this
one moves the money plane to its 1.0 and the console composition and the two
tunnel images to the versions the stack-k8s `v1.0.0` tag published, after a
run on 2026-09-14 proved them. The installer itself is the one 1.0.0 shipped
(md5 `54826a5a…`, unchanged).

## Upgrade note, 1.0.0 to 1.1.0

Run the installer again. `.env` is never rewritten, only added to; `compose`
recreates only the five services whose image moved; the policy store and every
volume stay. The money plane's upgrade note (tokenfuse `docs/releases/v1.0.0.md`):
nothing to migrate, no name, default or wire body changed after 0.5.1, the
Parquet trace reads across versions. The tunnel keeps its keys (`wgstate`), so
enrolled peers keep working.

## Not in this release, said plainly

- **The console's Bus Explorer is empty** on this launcher, at 0.1.2 and at
  1.0.0 alike. The cause first written here (a reader stopping at a directory
  it cannot read) was wrong: the console keeps its bus history under
  `<TAIPAN_HOME>/genaryx`, and `TAIPAN_HOME` here is a root-owned config
  mount it cannot write, so the store is never created (genaryx#71, #49,
  measured 2026-09-14 after this release). Invisible to the 22 checks, which
  ask the console to resolve the planes, not to read the bus. Fixed in the
  console (genaryx#72) and here by naming the state volume in
  `GENARYX_STATE_DIR` and a 23rd check (1.1.1).
- No arm64 run on this set (every 1.0.0 image is a linux/amd64 and linux/arm64
  manifest list; the 2026-09-13 arm64 run was on the 0.x pins).
- The browser and record profiles were pulled by nobody in this run; scopyx and
  trailryx-node are unchanged since 1.0.0.
- Notifications need `ALERT_TO` and an SMTP host; the run gave it neither.
