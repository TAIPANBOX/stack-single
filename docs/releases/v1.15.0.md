# stack-single 1.15.0

A minor release. Keyryx custody rotates and revokes only on its own admin socket and announces each change on the event bus, the notifier reads those announcements, vouchryx refuses an actor credential that is not bound to a key, and the console moves to genaryx's own release image, with three new read-only tabs.

## Upgrade first

1. **Run the installer.** No new file and no new setting is needed. keyryx (custody and witness), vouchryx, heraldyx, the console, verdryx-slo and verdryx-drift are recreated on their new pins; init-volumes makes custody's stream, `keyryx-custody.ndjson`. The rollback index stays 1.
2. **Agent tokens pause for about two minutes** while vouchryx is recreated and keyryx publishes its new working key ahead of use (`KEYRYX_PUBLISH_AHEAD`, 2m). Tokens already issued keep working.
3. **An actor credential must be bound to a key.** vouchryx 0.9.0 refuses a token exchange whose actor token carries no `cnf.jkt` (`invalid_grant`, `actor_credential_unbound` in vouchryx's log). The agents this launcher enrols use `client_credentials` with DPoP and are bound. A client of your own that sends a bearer provider token as the actor has to bind it with DPoP, or use vouchryx's own agent credential.
4. **Rotating a Keyryx key** is now `sudo docker compose exec keyryx keyryx admin rotate <name>` or `... revoke <kid>`. There never was a network admin key on this launcher, and keyryx 0.2.0 refuses to start with one. Rotating `keyryx.delegation-root` or `trailryx-root` means re-pinning them; the README says how.
5. **A `CONSOLE_IMAGE` in `.env`** that names the older `ghcr.io/taipanbox/genaryx-console` is refused at the signature check: the console now comes from genaryx's own release workflow, and stack-k8s's console image workflow is no longer an accepted signer. Remove the line to run the pinned console. A box built from source has its `CONSOLE_IMAGE=stack/genaryx-console:dev` line moved to `stack/genaryx:dev`.
6. **Going back to 1.14.1** needs nothing special. keyryx's own notes give running 0.1.5 again as its rollback; `keyryx-custody.ndjson` stays on the bus and nothing reads it.

## What changed

- **Keyryx custody announces on the bus** (invariant 86): keyryx v0.1.5 `967dd499` to v0.2.0 `ead031a1`, custody and witness on one pin. `KEYRYX_EVENTS=/var/lib/stack/events/keyryx-custody.ndjson`, made by init-volumes for custody's uid (20101:10001, 0640), mounted read-write for that one stream; the live bus probe (invariant 83) asks that custody can append to it and to no other stream. `KEYRYX_ADMIN_KEYS` is set nowhere, and custody joins no group.
- **heraldyx** v0.9.1 `ad1b03a2` to v0.10.0 `7baa8cdb`: reads custody's stream as source keyryx, so a `key_revoked` (high) is mailed and a `key_rotated` (info) goes in the digest. Its checkpoint gate stays off, because no producer on this box signs checkpoints yet.
- **vouchryx** v0.8.0 `2e184815` to v0.9.0 `341cc2c5`: unbound actor credentials are refused on a first hop.
- **The console on genaryx v0.1.0** (invariant 87): `genaryx-console` v1.14.0 `583fcbe1` to `ghcr.io/taipanbox/genaryx` v0.1.0 `4030bc81`, for the console, verdryx-slo and verdryx-drift. The Notifications tab reads heraldyx's journal, the Keys tab reads custody's state and inventory, and the Record tab reads the record seal's data and verifies a pack on request, each read only. `BUILD_FROM_SOURCE` builds genaryx's own Dockerfile. The installer finds the console's image by its service, not by the first image compose lists.
- **The image signer** no longer accepts `stack-k8s/.github/workflows/console-image.yml`.

## Evidence

- Both new gates were red on 1.14.1's tree (7 and 8 failures) and are green here; each has teeth cases.
- A review of the diff found that `docker compose config --images console` lists the console's dependencies too, in no fixed order, so the first draft asked a random image for the approver key set and every install leg stopped; the approver and preview gates now model that list and went red on the first draft.
- CI on the release head: every install leg, `browser`, `upgrade`, `upgrade-tool-hold` and `piped`.
