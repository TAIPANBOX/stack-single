# stack-single 1.1.11

TokenFuse moves to 1.4.0 and the policy plane to 1.1.1.

## What changed

- **`tokenfuse:v1.4.0` and `tokenfuse-control-plane:v1.4.0`** (were v1.3.0),
  for the gateway, `focus-export`, the MCP broker and the control plane. A
  call's cost now rounds once, on the sum, toward over-charging (it rounded
  each part down); a refused delegation proof answers `401 delegation_refused`
  instead of asking for a client key, and the gateway's log names the cause.
- **`wardryx:v1.1.1`** (was v1.1.0). A policy that sets `deny_above_usd` or
  `require_human_above_usd` to `0` now means it; before, a zero was read as
  "no rule". Existing policies keep their `PolicyVersion`.

## Measured

On 2026-09-27 the same images ran together on a three-node cluster (stack-k8s
1.1.16's set): its security checks and verify passed in full, and a
`deny_above_usd: 0` policy written through wardryx's API refused the next call
before the provider.

## Upgrade

Re-run `install.sh` on the box. The images are pulled; `.env` is left as it is.

## Not in this release, said plainly

- A full `install.sh` run with this pinned set was not made on a box; the
  images ran on a cluster.
