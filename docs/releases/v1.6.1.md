# stack-single 1.6.1

A patch release. The box moves to tokenfuse v1.22.0, scopyx v1.3.0 and the console and tunnel images of stack-k8s v1.8.1, so a read of the web reaches Scopyx under the run that asked for it, and the broker no longer follows a redirect.

## Upgrade first

1. **Run `./install.sh` again from this release.** A box with its own operator files names them as before (`CLIENT_KEYS_FILE=... IDENTITY_MAP_FILE=...`). Each image moves by tag and digest:

   | Image | 1.6.0 | 1.6.1 |
   |---|---|---|
   | tokenfuse (gateway, MCP broker, sidecars) | v1.21.0 | v1.22.0 |
   | tokenfuse-control-plane | v1.21.0 | v1.22.0 |
   | scopyx, scopyx chromium | v1.2.0 | v1.3.0 |
   | genaryx-console | v1.7.5 | v1.8.1 |
   | stack-caddy, stack-wg | v1.7.3 | v1.8.1 |

2. **The MCP broker follows no redirect.** An upstream that answers 301, 302, 307 or 308 now fails with `upstream error: answered ...`. The two upstreams this box names, `http://typryx:4320/mcp` and `http://scopyx:4300`, answer directly.
3. **A call that searched on the OpenAI door labels its run.** A run that went on to ask for a shell can now be refused where it was not before. The record is the existing `taint_raised` event.
4. **A figure you compare across this release can rise.** A body that stopped short is charged the input as reported and the output at the request's cap, under the cost basis `PartialUsage`.

## What changed

- **A fetch joins its run.** With agent tokens on, the broker forwards `x-fuse-run-id` to `scopyx`, the upstream named in `BROKER_UPSTREAM_LABELS`, and to no other, and Scopyx 1.3.0 records the fetch under that run.
- **The broker's own security fixes.** tokenfuse v1.22.0 stops the broker's client following redirects, which could have sent the secrets it wrote into a body to a host an upstream named, and holds a tool call that arrives in a closing `message` chunk.
- **The console's engines are the box's own.** genaryx-console v1.8.1 carries tokenfuse v1.22.0 and wardryx v2.5.1, the digests this box runs.
- **`stack-caddy` carries Caddy 2.11.8,** built on go1.27.3 with `caddy-dns/cloudflare` v0.2.4.

## Measured

- CI ran `install.sh` for real, twice, on a fresh Ubuntu runner in six profiles, on these pins.
- Every digest was read from ghcr.io with `docker buildx imagetools inspect` after its release run ended, and each image is signed for amd64 and arm64.
- The published console, by digest: `tokenfuse --version` printed `tokenfuse v1.22.0 (ba81a1d)`, and its engine labels carry the digests the box pins.
