# stack-single 1.1.26

TokenFuse moves to `v1.10.0` and heraldyx to `v0.4.0`: a retained call and a
person's closure of it now reach the event bus and the notifier's mail, and
the MCP broker waits long enough for a policy decision that takes more than
50 ms.

## What moves

- **TokenFuse `v1.9.0` -> `v1.10.0`**: the gateway, the MCP broker, the
  `focus-export` job (`TOKENFUSE_IMAGE`) and the control plane
  (`TOKENFUSE_CLOUD_IMAGE`). Release notes:
  [tokenfuse v1.10.0](https://github.com/TAIPANBOX/tokenfuse/releases/tag/v1.10.0).
  - **`call_retained` (medium)** when the gateway retains a call whose outcome
    became unknown, and **`retained_closed` (high)** when a person closes one
    with evidence (D10, agent-passport SPEC 6.2). The gateway here already
    writes `tokenfuse.ndjson` on the bus, so both reach heraldyx with no
    configuration.
  - **The broker's policy deadline defaults to 1000 ms** on the tool path. The
    broker here asks a policy plane only with `TYPED_RISK_SIGNAL=1`, and then
    its deadline is set to 7000 ms, so nothing on this box changes behaviour.
- **heraldyx `v0.3.0` -> `v0.4.0`** (`HERALDYX_IMAGE`). Release notes:
  [heraldyx v0.4.0](https://github.com/TAIPANBOX/heraldyx/releases/tag/v0.4.0).
  - Both new TokenFuse types are described in the mail; the evidence
    reference a person typed is never mailed (only the reservation id and the
    amounts are).
  - agent-conform's `chain_broken` and `chain_unchained`, which this box's
    chain verifier writes, are described instead of the generic wording.

No other pin moves.

## Measured

The gateway, control plane and console as this compose file wires them, with
`tokenfuse:v1.10.0`, `tokenfuse-control-plane:v1.10.0`,
`genaryx-console:v1.1.36`, `heraldyx:v0.4.0` and a stub provider, on Docker
Compose, 2026-10-12: 44 of 44 checks, twice from empty
([stack-k8s evidence/closure-verified.md](https://github.com/TAIPANBOX/stack-k8s/blob/main/evidence/closure-verified.md),
"The bus and the mail", and the harness beside it). One `call_retained` per
retained call, one `retained_closed` per applied closure, none for a refused
or repeated close or on a restart's replay, and a mail describing each with no
evidence reference. Against `tokenfuse:v1.9.0` the same harness failed the 7
checks on the bus and in the mail.

## Upgrading

- **Nothing to configure.**
- **The alert floor here is `high`** (`ALERT_MIN_SEVERITY`), so
  `retained_closed` is mailed as it happens and `call_retained` (medium) lands
  in the daily summary. A retained call whose provider connection broke also
  mails `dependency_failed` (high) at once. Set `ALERT_MIN_SEVERITY=medium` in
  `.env` to have every retained call mailed as it happens.

## Not proven

- **`install.sh` with these pins on Debian by hand.** CI's install legs run
  it on Ubuntu.
- **The record over these events.** trailryx maps both types on its `main`
  (trailryx#94), but the `trailryx-node` release `record-seal` pins predates
  that mapping, so the record refuses them until trailryx is released and
  pinned.
- **A call retained because the caller left**, rather than because the
  provider's connection broke, was not run.
