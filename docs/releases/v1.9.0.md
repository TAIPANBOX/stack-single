# stack-single 1.9.0

A minor release. A container of another project on the box can now reach the stack through a `guests` network that holds the doors and nothing behind them, and `status` names it where `guests.txt` and that network agree. TokenFuse moves to v1.25.0 (a person's delegation rides beside an agent's own token), vouchryx to v0.8.0 (scoped revoke keys), and the Go services the box runs are rebuilt on Go 1.27.4.

## Upgrade first

1. **Nothing is required before the first run.** The `guests` network is new and empty; no `.env` value, key, map entry or volume changes, and the rollback index stays 1.
2. **A box that already lets a foreign container onto `agent-stack_core` should move it.** Before this release such a container (on one box, a lab's gateway and its identity bridge) joined `core`, because vouchryx was on `core` alone, and from there it could address every plane, the policy database and custody. Put the container on `agent-stack_guests`, which holds exactly vouchryx, `tokenfuse-gateway` and `tokenfuse-mcp-broker` and is `internal`, and list its name in `guests.txt` beside `compose.yaml`, one container name per line. The operator writes that file; the installer never writes, copies over or removes it. A guest then gets tokens, model calls and tool calls through the doors an agent uses and reaches no plane, no database and no custody.
3. **`status` reads `guests.txt`.** A named container on the guests network is a note. An unnamed container there is the `unknown container` FAIL it always was. A named container on any other network of the stack is a FAIL, because the rule is in the code: no line lets a guest onto `core`. A `guests.txt` that cannot be read, or a line that is not one container name, lets nobody in and counts as could-not-measure.
4. **TokenFuse v1.25.0 adds two request headers and changes nothing for a client that sends neither.** Under `TOKENFUSE_AGENT_TOKENS=require`, which this launcher runs, an agent acting for a person may send `x-fuse-delegation` and `x-fuse-delegation-dpop` beside its own token; the policy plane is then told the person's chain as proven. A proxy in front of the gateway must forward both. The box's own agents send neither. TokenFuse also prices `claude-fable-5-2` at its own row (8 / 40 USD per million tokens) where it was billed at the fallback rate.
5. **Going back to 1.8.0 needs nothing special.** The rollback index stays 1. The `guests` network stays on the box, unused, and 1.8.0's `status` reports a container on it as unknown, as it did before.

## What is new

- **A `guests` network** (#187, CLAUDE.md invariant 77). `compose.yaml` declares it `internal`, with exactly vouchryx, `tokenfuse-gateway` and `tokenfuse-mcp-broker`; the gateway and the broker stay on `core` as well. `scripts/network-membership.sh` holds the members, the `internal` flag and a probe in CI; `scripts/status-reads-what-runs.sh` holds the `status` rules with eight fixture cases.
- **The pins** (#186, #188): vouchryx v0.8.0, TokenFuse v1.25.0 and the Go 1.27.4 rebuilds listed above. The gates that name a pin (`images-are-digest-pinned.sh`, `images-are-verified.sh`, `typed-data-mode.sh` and the pin cases of `gates-have-teeth.sh`) read the new ones.

## Evidence

- CI on the release head: every install leg, `browser`, `upgrade` and `upgrade-tool-hold`, with the guests probe on a real Docker, green.
- The `guests` gates were run red first on the tree before them (#187): `network-membership.sh` against the old `compose.yaml` finds five distinct problems and `status-reads-what-runs.sh` against the old `install.sh` finds 21.
