# stack-single 1.1.7

One installer check, no image moves. The pinned set is exactly 1.1.6's.

## What changed

The installer's verify step asks one more question: `policy plane reaches
its store`, a probe of wardryx's `GET /readyz` (wardryx 1.0.3). The check
before it, `policy store is up`, asks the database whether it is running.
This one asks wardryx whether it can reach that database with the DSN and
the network it was given. A wrong `WARDRYX_DB`, or a store the policy plane
cannot resolve, used to pass the whole verify step while every policy write
failed; it now reads FAIL (#66).

Nothing routes on it. wardryx has no compose healthcheck (its image carries
no shell), and decisions do not depend on the store, so a store outage must
not take the decision path away.

## Upgrade

Re-run `install.sh` on the box. `.env` is left as it is; no image is pulled
that 1.1.6 did not already pull.

## Not in this release, said plainly

- A full install with this check was not run on a fresh box. Its probe was
  run on its own: it passes against a live wardryx 1.0.3 and fails against a
  `/readyz` that answers 503.
