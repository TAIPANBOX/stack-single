# stack-single 1.1.1

The console's Bus Explorer, empty on every install of this launcher since
2026-08-31, fills (#49, genaryx#71). The console keeps its bus history in a
store it creates at startup; it created it under `TAIPAN_HOME`, which this
launcher points at a root-owned config mount, so the store never existed and
the console logged one `Permission denied` line and served on. Nothing else
in the pinned set moves.

## What changed

| Piece | Change |
|---|---|
| console | `genaryx-console:v1.1.1` (was v1.0.0): the stack-k8s v1.1.1 tag's composition, genaryx main with #72, which asks for `GENARYX_STATE_DIR` first, then `<TAIPAN_HOME>/genaryx`, then `<HOME>/.taipan/genaryx`, and names a skipped candidate on stderr |
| `compose.yaml` | `GENARYX_STATE_DIR: /var/lib/stack/genaryx` on the console: the state volume, said outright |
| `install.sh` | a 23rd check, `console's bus is live`, reading the console's own startup line (`bus LIVE`, never `bus startup failed`); the 22 were green through the whole outage |
| `install.sh` | `check_log()`: the two log-read checks are retried for up to ten seconds; a one-shot read raced the log driver once on an arm64 box (a line stamped nine seconds before the check, ok on the next run, same container) |

The 1.1.0 notes' sentence naming a reader that stops at an unreadable
directory was wrong and is corrected there.

## Proven, on a fresh arm64 box (estate-gates `PROVEN.md`)

- **INS-3, R1 GCP `t2a-standard-2`, 2026-09-14.** The README one-liner from
  the release branch: 90 s, 22 ok and the one log-read race (finding 1 of the
  rig); again 25 s, **23 ok, 0 fail**, the container set byte-identical;
  a third time with `check_log`, 42 s, 23 ok. Every image pulled is the
  `linux/arm64` manifest, postgres included: the arm64 gap of the 1.1 set is
  closed.
- **The console at 1.1.1.** `bus LIVE on environment "single"` at startup,
  `console.sqlite` at `/var/lib/stack/genaryx/single/`; after a budgeted run
  through the stand's gateway to the real Anthropic API (17 calls, the 18th
  `402`), the console's store holds wardryx's `policy_allow` rows and the
  gateway's `breaker_tripped`: gateway to bus to console, end to end.

## Upgrade note, 1.1.0 to 1.1.1

Run the installer again: `compose` recreates the console only, with the new
variable; the state volume is where the store lands; nothing to migrate,
because the console never managed to create the old store anywhere. The
23rd check will be red on a box whose console is older than v1.1.1, which is
the honest reading of that box.

## Not in this release, said plainly

- The Bus Explorer was read through its store and its startup line, not
  through a browser session.
- x86 was not re-run on this set (the morning's x86 run was on 1.1.0 with the
  v1.0.0 console; the images are the same manifest lists).
