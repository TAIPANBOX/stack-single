# stack-single 1.1.25

The console moves to `genaryx-console:v1.1.36`, the first that signs in an
operator set while it is already running, with no restart (stack-k8s
GOTCHAS 50).

## What moves

- **Console `v1.1.34` -> `v1.1.36`** (`CONSOLE_IMAGE`, the console and the
  `verdryx-drift` routine), built by stack-k8s tag v1.1.36 from genaryx
  `41972c6` (genaryx#106).
  - **An operator set after the console started signs in at the next
    attempt.** The console used to read whether it had an operator once, at
    startup, which is why 1.1.24 had to restart it right after creating the
    operator (#107). It now reads `operator.json` again while it holds none.
  - **A password changed on a running console still needs a restart.** An
    operator the console already holds is never read again, as before. This
    installer never changes an existing operator's password, so nothing here
    depends on it.
  - `set-password` says this on stderr, and the console's startup warning says
    the next sign-in picks a new account up.

No other pin moves. The restart from #107 stays: with this console it is
redundant and costs a few seconds, and it still matters for a `CONSOLE_IMAGE`
set to an older console.

## Measured

The console as this compose file wires it beside the gateway and the control
plane, with `tokenfuse:v1.9.0` and `tokenfuse-control-plane:v1.9.0` and a stub
provider, on Docker Compose, 2026-10-12, through stack-k8s'
`evidence/closure-e2e/run.sh`, which now sets the operator inside the running
console and does not restart it
([stack-k8s evidence/closure-verified.md](https://github.com/TAIPANBOX/stack-k8s/blob/main/evidence/closure-verified.md)):

- **`genaryx-console:v1.1.35`** (genaryx `2317d80`): 16 failed. The running
  console still said it had no operator after `set-password`, and sign-in
  answered 503.
- **`genaryx-console:v1.1.36`** (genaryx `41972c6`): 32 of 32, twice from
  empty.

This installer itself on the new console is what CI's three install legs run
on this change.

## Upgrading

- **Nothing to configure.** A re-run of `./install.sh` from this release pulls
  the new console; `.env` is not rewritten. The operator account and passkeys
  carry over, and operators sign in again once the console has restarted, as
  after any console restart.

## Not proven

- **A password changed on a running console** is unchanged by this release and
  was not re-measured.
