# stack-single 1.1.32

TokenFuse moves from `v1.11.0` to `v1.13.0`, across two releases. The gateway
and the MCP broker now judge a run that holds the agent's memory as untrusted
context, exit at start on a mistyped security switch instead of running in its
weaker mode, and price Claude Haiku 5.5 from its vendor rate. This tag also
carries the opt-in client keys and identity map as files (#115), merged after
v1.1.31. On this launcher's default install the firewall stays in enforce, as it
has been since 1.1.29, and the MCP broker is not started (see Upgrading). This tag also moves Wardryx to
v1.3.2, scopyx to v1.0.1, the console to v1.1.43, the two tunnel images to v1.1.43 and costcrew to v0.6.0.

## What moves

  `compose.yaml` passes the console `GENARYX_COPILOT_FUSE_KEY_REF` and
  `GENARYX_COPILOT_FUSE_KEY` from `.env`, empty by default, so nothing changes
  unless an operator sets it. The console pinned in this tag (`v1.1.43`) was
  built before genaryx gained the setting and ignores both lines; a later
  console that carries genaryx invariant 24 sends the key as `x-fuse-key`. Steps:
  README, "Client keys and the identity map".
- **TokenFuse `v1.11.0` -> `v1.13.0`**: the gateway, the MCP broker, the

    Both list `linux/amd64` and `linux/arm64`.
  - **The memory label (v1.12.0, invariant 95).** A run whose prompt holds the
    agent's memory is judged like a run that read a web page. The built-in source
    map labels the output of Engram's `recall` and `why` tools as `memory`, and a
    framework can declare it with the `x-fuse-taint: memory` header. Under the
    starter policy such a run cannot then run a command, write, or reach the
    network.
  - **Mistyped security switches exit at start (v1.12.0, invariant 98).** Nine
    switches refuse a value they cannot read. Which of them this launcher sets is
    listed under Upgrading.
  - **Prices (v1.13.0, invariant 99).** Claude Haiku 5.5 is priced at its vendor
    rate, where it settled at the 15 / 75 fallback before, and a call above 100,000
    prompt tokens is priced at its long-prompt rate. Claude Sonnet 5.5 cache hits
    are priced at 0.10 per million tokens, where the row had 0.20.
  - No environment name is added or removed, and no setting is needed. This
    launcher sets no price book file.
- **Client keys and the identity map as files (#115, invariant 29, merged after

## Upgrading

- **This launcher writes only accepted words.** TokenFuse v1.12.0 made nine
  switches exit 2 on any value outside their words (case does not matter). Each
  one this launcher touches, and where it is set:

  | Switch | Accepted words | This launcher |
  |---|---|---|
  | `TOKENFUSE_DLP_PII` | off, shadow, mask, block | `${TOKENFUSE_DLP_PII:-shadow}` on the gateway (`compose.yaml:921`); install.sh section 0e writes it only when set |
  | `TOKENFUSE_MCP_DLP_PII` | off, shadow, mask, block | `${TOKENFUSE_DLP_PII:-shadow}` on the broker (`compose.yaml:648`) |
  | `TOKENFUSE_WARDRYX_MODE` | off, shadow, enforce | `enforce` on the gateway (`compose.yaml:956`); `${TYPED_RISK_WARDRYX_MODE:-off}` on the broker (`compose.yaml:666`), which install.sh sets to `enforce` only when the typed risk signal is on (`install.sh:481`) |
  | `TOKENFUSE_WARDRYX_FAILMODE` | open, closed | `closed` on the gateway (`compose.yaml:961`) and the broker (`compose.yaml:671`) |
  | `TOKENFUSE_MCP_DLP` | off, shadow, block | not set |
  | `TOKENFUSE_MCP_SCAN` | off, warn, block | not set; unset reads as warn |
  | `TOKENFUSE_MCP_TAINT_FAILMODE` | open, closed | not set |
  | `TOKENFUSE_MCP_REQUIRE_PROOF` | 0, false, 1, true | not set |
  | `TOKENFUSE_MCP_REQUIRE_SECRET_SCOPES` | 0, false, 1, true | not set |

  The firewall switch, `TOKENFUSE_FIREWALL` (refused since v1.11.1), is
  `${TOKENFUSE_FIREWALL:-enforce}` on the gateway (`compose.yaml:914`), and
  install.sh section 0d writes only `enforce`, `shadow` or `off`. Checked by
  grep across the tree at this commit; no other file sets these names.
- **Where an operator's value could be refused.** install.sh checks
  `TOKENFUSE_DLP_PII` and `TOKENFUSE_FIREWALL`, from the shell and from `.env`,
  before anything is installed or written, so a value it refuses never starts.
  Two values reach compose without that check: a `TOKENFUSE_DLP_PII` or
  `TOKENFUSE_FIREWALL` exported in the shell of a plain `docker compose up`, and
  a `TYPED_RISK_WARDRYX_MODE` exported in that shell, which install.sh does not
  read. A word outside the list above in either place makes the gateway or the
  broker exit 2 at start, and the container log names the variable and the value.
  No value this launcher writes is refused.
- **The firewall stays in enforce.** It has been enforce by default since 1.1.29.
  With the memory label, a run that has read memory cannot then exec, write or
  reach the network under the starter policy. Nothing here measures that path.
- **Calls on the newly listed models are charged at vendor rates.** A budget sized
  against fallback-priced calls now admits more of them. The answers carry
  `x-fuse-price: known` where they carried `fallback`.
- **No setting changes.** The launcher sets no price book file, no firewall policy
  file, no `TOKENFUSE_MCP_SCAN`, no `TOKENFUSE_MCP_LOCK`. A default install does
  not start the MCP broker (it sits in the `typed` profile). Enabling any of these
  is a separate decision, not made in this release.

### New pins: what changes for a deployment

- **Wardryx 1.3.1 and 1.3.2: what now loads that did not.** From 1.3.1 a policy file
  loads every YAML document (separated by `---`) and every JSON value. Before, only the
  first was read and the rest were dropped with no error. A later document with a
  misspelt field, or a value of the wrong type, now stops `serve` at start and the error
  names it. Both policy files this launcher ships hold one document: `install.sh` writes
  `policy.yaml` (section 4) as one YAML document of three policies, and
  `examples/policy-hardened.yaml` is one document. Neither changes its verdicts on this
  upgrade. The seeded `mockryx-allow-list` uses `allow_tool`, which needs Wardryx v1.3.0
  or later; this pin is later. From 1.3.2 a PUT whose body holds a key the policy does
  not declare is refused with a 400, where it used to be stored without the key and
  answered 200. The console code in this launcher's pin names its guarded policy editor
  as a later version (genaryx `crates/api/src/policy/commands.rs`, line 475, at
  `4fc39b3`), so no PUT from it is expected. That is read from the comment, not run.
- **scopyx 1.0.1.** On the chromium backend every subresource of a page is decided
  against the policy plane. A page whose subresource host the policy refuses now renders
  without that subresource, and the record counts it. Before, such a host was reached.
  A rendered page costs the policy plane one `/v1/decide` per distinct subresource host.
- **Console v1.1.43.** The genaryx source changed by one commit between the two builds,
  `4fc39b3` (#107), and that commit edits `CLAUDE.md` only. The image's build labels also
  name engram (one commit, memory provenance, #58) and mockryx (four commits, drill
  scenarios) sources, so the image carries those changes too. What the bundled engram and
  mockryx changes do inside this launcher was not run here. No setting changes.
- **stack-caddy v1.1.43.** The Dockerfile is identical at both source revisions. Its base
  images are the floating tags `caddy:2-builder-alpine` and `caddy:2-alpine`, so the image
  content can move with upstream Caddy 2.x. Not measured.
- **stack-wg v1.1.43.** The build stage moves to `golang:1.27.2-alpine`, the Go 1.27.2
  toolchain. The runtime base `alpine:3.20` is unchanged. No setting changes.
- **costcrew v0.6.0.** A new decision class, `driver.announced`: a cost decision the crew
  recommends can be announced before it lands, and only the owner's answer applies it.
  Two nullable columns are added to `drivers` at start (`expected_daily_cents`, `team`);
  rows written earlier read NULL and behave as before, and no data is rewritten. The
  Anthropic rows in the price table move to the vendor's list rates (Sonnet 5 at 2.00 /
  10.00, Opus 5 at 5.00 / 25.00 per million tokens). costcrew is an opt-in add-on: this
  pin starts nothing, and as shipped it still cannot spend because no gateway is wired to
  it.

## Not proven

- **`install.sh` with these pins on a box.** CI's install legs run it on Ubuntu.
- **A live run of v1.13.0 against a real provider.** No model call was made for
  this release. Upstream says the rates are true on 2026-10-13 only, and that the
  OpenAI, DeepSeek, Moonshot and Z.ai rows were not re-read that day.
- **The memory label and the enforce floor on this launcher.** Upstream measured
  them by tests through CI, not on this compose stack.
- **Mistyped switches refusing at start, on this compose stack.** Upstream
  measured the refusal on the image; no run here starts the stack with a bad word.
- **The new pins on a running stack.** No `docker compose up` was run with them here.
  `install.sh` on Debian with these pins is not run here either; CI runs it.
- **Wardryx 1.3.1 and 1.3.2 against a live policy file or a live PUT.** Read from the
  release notes; the upstream notes say they did not read live traffic either.
- **The bundled engram and mockryx changes inside the console image.** Named from the
  build labels; their effect on this launcher was not measured.
- **stack-caddy content.** Its Dockerfile is unchanged, but the floating base image is
  not measured.
- **costcrew v0.6.0 in a running stack.** Adopted and pinned, but not started here. Its
  behaviour is what its release notes say, not what this launcher ran.
