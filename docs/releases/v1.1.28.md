# stack-single 1.1.28

TokenFuse moves to `v1.11.0`. The gateway and the MCP broker now read what a
tool says about itself, not only its name, and a tool whose definition changed
since it was pinned can be refused where the broker is set to `block`. On this
launcher the gateway's firewall runs in shadow, a default install does not start
the broker, and no lockfile is set, so the change records and labels here and
refuses nothing (see Upgrading).

## What moves

- **TokenFuse `v1.10.0` -> `v1.11.0`**: the gateway, the MCP broker, the
  `focus-export` job (`TOKENFUSE_IMAGE`) and the control plane
  (`TOKENFUSE_CLOUD_IMAGE`). Release notes:
  [tokenfuse v1.11.0](https://github.com/TAIPANBOX/tokenfuse/releases/tag/v1.11.0).
  - Index digests, read with `docker buildx imagetools inspect`:
    `tokenfuse` `sha256:ce983204dcb603bead1d45b56ed2f6aee5e1db02416757c3f60f100eaa7fc605`,
    `tokenfuse-control-plane` `sha256:6e074b57d0b34e749246e72fb5159dd27fbfc650aa30ed5127f8af82bbb69ee1`.
  - **The scan reads tool metadata (invariant 92).** `mcp-scan` and the broker
    read each tool's description and every parameter description for a
    credential, an order to run another tool, a local credential path, text
    addressed to the model and hidden text, beside the stock phrases they
    already matched. Each finding carries a kind and a severity.
  - **A drifted tool cannot be called (invariant 91).** With the broker's scan
    set to `block` and a lockfile of pinned tools, a `tools/call` for a tool
    whose definition changed since it was pinned is refused. In `warn` the call
    is forwarded and logged once.
  - **Declared tools are read for poisoning (invariant 93).** The gateway reads
    the tools a request declares. A high or critical finding labels the run
    `suspected_injection`. The request is never refused for what a description
    says.
  - **quinn-proto `0.11.15` -> `0.11.19`** (RUSTSEC-2026-0338 to 0342), inside
    the image. Nothing in this repository changes for it.

No other pin moves.

## Upgrading

- **Nothing to configure.** This launcher sets neither `TOKENFUSE_FIREWALL`,
  nor `TOKENFUSE_MCP_SCAN`, nor `TOKENFUSE_MCP_LOCK`, and adds no variable.
- **The gateway firewall runs in shadow on this launcher.** TokenFuse reads an
  unset `TOKENFUSE_FIREWALL` as shadow. A poisoned declared tool is labelled and
  recorded, not refused: the run is labelled `suspected_injection`, a
  `taint_raised` event (low) is written, and a later action the firewall would
  stop is written as `taint_shadow` (medium) and allowed. Nothing is refused or
  denied.
- **Neither event is mailed here.** The alert floor on this box is `high`
  (`ALERT_MIN_SEVERITY`), so both stay on the event bus.
- **A default install does not start the MCP broker.** The broker sits in the
  `typed` profile, which starts only with `WITH_TYPED=1` or a `TYPED_MODE`.
  Where it runs, its scan is `warn`, which is what an unset `TOKENFUSE_MCP_SCAN`
  reads as: findings are logged and the listing is forwarded. Nothing is refused.
- **Invariant 91 is inert on this launcher.** The drift check needs a lockfile
  named by `TOKENFUSE_MCP_LOCK`, and this launcher does not set it. With no
  lockfile no tool is pinned, so no tool can be seen to change, in any scan
  mode. The `refused-tool-changed` decision word appears only in `block`, which
  this launcher does not set.
- **Enabling any of these is a separate decision, not made in this release.**
  Setting the firewall to `enforce`, setting the broker scan to `block`,
  starting the typed plane, or setting `TOKENFUSE_MCP_LOCK` each changes what
  this box refuses. Each needs its own decision.

## Not proven

- **`install.sh` with these pins on Debian by hand.** CI's install legs run it
  on Ubuntu.
- **A live run of v1.11.0 against a real provider, or against a poisoned tool
  listing.** The upstream release notes say the same: the changes were measured
  by tests through CI. No model call was made for this release.
- **Invariants 91 and 92 on the broker, on this launcher.** A default install
  does not start the broker, and no lockfile is set, so the drift check is not
  exercised here.
- **Limits from upstream.** The drift state lives in the broker process, so a
  restart forgets it. The scan reads shapes, not meaning. Declared tools are
  not pinned across turns.
