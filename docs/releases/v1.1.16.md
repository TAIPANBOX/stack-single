# stack-single 1.1.16

Typed answers now ask where your data goes, and typryx moves to `v0.3.0`.

- `TYPED_MODE=jev|own-model|off` (default `off`; `WITH_TYPED=1` alone still
  gives the stub backend, with a byte-identical `.env`). `jev` sends the fields
  a template names to TypeSafe AI's hosted API; `own-model` points typryx at
  your own OpenAI-compatible server (Ollama, vLLM), so nothing leaves your
  hardware. A key is only ever a file: copied into `./typed` (mode 0400, owned
  by typryx's uid), mounted read-only, never in `.env` or any output; a
  missing, empty or blank key file is refused before anything is installed.
  Compose now passes the backend variables into the container, reaches a model
  server on the same host through `host.docker.internal`, and gives own-model a
  30 s timeout.
- typryx pinned to `v0.3.0`: a distribution rounded to four decimals is
  answered, and an opt-in local training log is available.
- `TYPED_TRAINING=1` (off by default) keeps typryx's training log on the
  `typryxdata` volume beside the ledger, so `typryx export --training` can pair
  logged questions with the truths a person posted.

Measured on a development Mac, 2026-09-30, through compose with the installer's
own `.env` block: own-model against a local qwen2.5:7b answered an ask that
carried an extra `user_email`, a posted truth was exported as one row holding
only the template's fields, the email in no line, the training dir 0700 and the
file 0600. CI install (default) and install (delegation) green on #84 and #85.
Not run: a full `install.sh` on Debian in any typed mode.
