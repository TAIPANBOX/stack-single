# stack-single 1.1.27

trailryx-node moves to `v1.2.0`, so the record plane seals the two money-held
event types TokenFuse 1.10.0 writes. Until now `record-seal` refused both and
moved its position past them.

## What moves

- **trailryx-node `v1.0.0` -> `v1.2.0`** (`record-seal`: the `TRAILRYX_IMAGE`
  default in `compose.yaml`, and `components.json`). Release notes:
  [trailryx v1.2.0](https://github.com/TAIPANBOX/trailryx/releases/tag/v1.2.0).
  - **`call_retained` (medium)** is a call whose outcome became unknown, so its
    money stays reserved until a person closes it. **`retained_closed` (high)**
    is that closure. TokenFuse 1.10.0 writes both to `tokenfuse.ndjson`, which
    this box already puts on the bus (see 1.1.26). trailryx-node 1.0.0 refused
    both as unknown types.
  - Why this matters: `events` moves its position past a refused line, so a
    line refused by 1.0.0 is not read again by a later run, even one on a newer
    image. The record of those retained calls is lost for that data directory.

No other pin moves.

## Upgrade caveat: read before the pin moves

**A data directory whose position already passed a 1.0.0 refusal will not
re-read those lines after the pin moves.** This release does not reset that
position, and it does not re-read those lines. Lines refused before this change
stay unrecorded. trailryx 1.2.0 says the same about its own readers.

A new data directory records those lines from the start. An existing `records`
volume that has already run over them is covered by the caveat in full.

## Measured

Measured on 2026-10-12 on this Mac, with the published images
`ghcr.io/taipanbox/trailryx-node:v1.0.0` and `:v1.2.0`. The input was one
constructed `call_retained` envelope: the fixture in trailryx's own test suite
(`crates/trailryx-agentevent/tests/envelope.rs`, `TOKENFUSE_CALL_RETAINED`).
**It is not a line written by a running TokenFuse, and nothing here was run on
a live TokenFuse event.** Command, per case:
`trailryx-node events --file /work/bus/tokenfuse.ndjson --data <dir> --trust-domain acme.example --seal-records 500`.

| Case | Result |
|---|---|
| v1.0.0, fresh data directory | `unknown_type 1`, 0 records written, position committed past the line |
| v1.2.0, the same directory after the v1.0.0 run | `nothing new`, 0 records: the line is not read again |
| v1.2.0, fresh data directory | 1 line mapped, 1 record written, segment sealed with 2 records: the second is trailryx's note that one payload part was declined, since this launcher seals no payloads |

`retained_closed` is mapped according to trailryx 1.2.0's notes. It was not run
here.

## Not measured

- A line written by a running TokenFuse 1.10.0.
- `retained_closed` through `trailryx-node`.
- A pack from this run verified with `trailryx-verify`.
- The record over a full stack, or a cluster (see stack-k8s 1.1.39 for the
  cluster pin).
