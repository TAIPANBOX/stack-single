# stack-single 1.1.33

The console moves to `genaryx-console:v1.1.45`, TokenFuse to `v1.13.2`, and the other
pins to the releases of 2026-10-14: wardryx `v1.5.0`, idryx `v1.2.1`, heraldyx `v0.6.0`,
typryx `v0.4.1` and trailryx-node `v1.2.1`. This tag also carries what merged after
v1.1.32: an opt-in second TokenFuse gateway on the OpenAI wire (port 4110, invariant 32),
a secret minted from a bounded read so it cannot hang on a Mac (invariant 31), an
installer fix for the gateway probe after a bind change, and the typed risk signal's
README rule, which now holds a call the signal did not answer (`when_absent: hold`).

A default install starts nothing new. The OpenAI door is off unless `OPENAI_DOOR=1` is
set, the MCP broker stays out of a default install, and the firewall stays in enforce, as
it has since 1.1.29.

- **The typed risk signal's README rule carries `when_absent: hold`** (commit `a14a98d`).
  wardryx 1.4.0 or later reads it as: a tool call that arrives with no `action.risk_class`
  signal is held for a person instead of passed. The README and `scripts/typed-risk-signal.sh`
  require the rule and the 1.4.0 minimum. The launcher's installer writes no hold rule; an
  operator adds one (see Upgrading).
- **The OpenAI door, opt-in (invariant 32, commit `116c64c`).** `OPENAI_DOOR=1` runs
  `tokenfuse-gateway-openai` behind the `openai-door` profile, on `${GATEWAY_BIND:-127.0.0.1}:4110`,
  for agents whose SDK speaks `POST /v1/chat/completions`. It is the gateway's own image and
  command with the same hardened settings, its own stream (`tokenfuse-openai.ndjson`), its own
  data directory and its own identity map (`./identity-openai`). Its upstream, keys file and
  map are required: section 0g of `install.sh` refuses `OPENAI_DOOR=1` without them before
  anything is installed. The two identity maps may not declare the same unit id. Gate:
  `scripts/openai-door.sh`; scenarios: `features/the-openai-door.feature`; the CI install leg
  runs it against a stub upstream.
- **The installer's end-of-run gateway probe follows the bind in `.env` (commit `f508d6c`,
  #122).** After a bind change on an installed box, the probe used to check the address the
  run was given. It now reads `GATEWAY_BIND` from `.env`. Gate: `scripts/bind-is-honoured.sh`.
  The same change makes the run's checks survive a closed pipe (`scripts/checks-survive-a-closed-pipe.sh`)
  and rewrites the Felyx note at the end of a run to say what Felyx needs (its key, and a
  binding in the identity map when one is used).
- **Secrets are minted from a bounded read (invariant 31, commit `101ffb2`, #123).** `gen`
  reads 4096 bytes with `head -c`, keeps the alphabet with `tr` and cuts to length in bash, so
  no reader is left writing into a closed pipe. Before, on macOS, where git runs hooks with
  SIGPIPE ignored, `tr </dev/urandom` never exited and the pre-push hook hung in
  `delegation-key-reused-on-rerun.sh`. Gate: `scripts/gen-is-bounded.sh`, twelve teeth cases.
- **A correction to the v1.1.32 notes (commit `6641d00`, #121).** The range from TokenFuse
  v1.11.0 to v1.13.1 is four releases (v1.11.1, v1.12.0, v1.13.0, v1.13.1), and the notes now
  say so. Notes only; nothing runs differently.

## Upgrading

- **No new switch.** The launcher writes no TokenFuse switch that was not already accepted:
  the table in v1.1.32's Upgrading section still holds, and the firewall switch is still
  `${TOKENFUSE_FIREWALL:-enforce}`.
- **The OpenAI door is off unless asked.** A box that never set `OPENAI_DOOR=1` runs as
  before. To turn it on, name the upstream, the keys file and the identity map; the README
  section "A second door on the OpenAI wire" lists what the door does not do (its spend is not
  in the FOCUS export, and the console shows the 4100 gateway's runs only).
- **Typed risk signal: add `when_absent: hold` to a rule written before this tag.** A rule
  copied from the README before 1.1.33 has no `when_absent` line, so a tool call with no signal
  still passes. The line needs wardryx 1.4.0 or later; this tag pins 1.5.0. The price is that
  every call the proxy does not answer (down, slow, or its budget spent) waits for a person.
  Leave `WARDRYX_APPROVAL_SINGLE_USE` unset.
- **wardryx 1.5.0 `allow_models` is written by you.** This launcher seeds no model list, so
  every model passes until a policy names one. A decision under a list is never cached.
- **Console v1.1.45 against v1.1.44.** The genaryx source moved 39 commits. Named from the
  commit subjects, not run here: the live demo shows the full signed-in console; the Posture
  view shows the gateway's settings, keys and price book; unit month caps exist, and an admin
  can change a unit's cap; runs show only the models they are known to have used; a refused
  client key and a PII finding are shown as what they are; the Overview shows a gateway the
  Cloud has stopped hearing from. No setting changes. Felyx's own key stays empty by default,
  as before.
- **heraldyx 0.6.0, idryx 1.2.1, typryx 0.4.1 and trailryx-node 1.2.1.** Their release bodies
  list pull requests and name no setting change. Nothing in this launcher's settings moves.
- **TokenFuse 1.13.2.** Its notes say no configuration changes.
