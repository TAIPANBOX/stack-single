# stack-single 1.6.3

An agent whose error budget is spent now waits for a person, on every box, with nothing to turn on. wardryx has been able to do this since 2.5.0. Until this release no box ran the measurement, read the file or carried the rule.

## Upgrade first

1. **Decide who the hold covers before you run the installer.** It is on by default, for every agent, and the first measurement runs as the routine starts. An agent you attack on purpose has a spent budget, and so does one that does far heavier work than the rest of the fleet.

   ```sh
   SLO_HOLD_TARGET='agent://acme.example/*' ./install.sh   # one agent glob
   SLO_HOLD_TARGET=none ./install.sh                       # measure and record, hold nobody
   SLO_SIGNAL=0 ./install.sh                               # none of it
   ```

   Both are saved in `.env` and survive a re-run. `SLO_HOLD_TARGET=none` is the way to see what your fleet looks like first: every decision records the signal, and nothing is held.

2. **Run `./install.sh` again from this release.** A box with its own operator files names them as before. One image moves by tag and digest:

   | Image | 1.6.2 | 1.6.3 |
   |---|---|---|
   | genaryx-console (the console and the quality routines) | v1.8.1 | v1.8.4 |

3. **A box with a console of your own (`CONSOLE_IMAGE`) needs `verdryx` 0.3.0 and pyarrow in it,** or `verdryx-slo` restarts and says why.

## What changed

- **`verdryx-slo` measures every agent's error budget every six hours,** over the last 28 days of traffic on both doors, and appends to `verdryx.ndjson` on the bus when one is spent. It has no network and a read-only root, and it runs under a uid nothing else runs as.
- **wardryx reads that file, and one rule holds the agent.** `slo-burn-hold` is a block in `policy.yaml` between two marker lines the installer alone writes. Every other line stays yours.
- **A hold does not keep itself alive.** A held call is written to the trace, so the routine sets holds apart, and an agent on hold can earn its budget back while it keeps working.
- **A bad spell ends.** `verdryx` 0.3.0 measures the window it names, so a run stops counting once the window has passed it.
- **A file wardryx cannot believe holds nobody.** The signal can only add a hold, and every other control stands without it. `/readyz` says `signal_events` is `ok`, `unreadable` or `broken`.
- **The console image carries pyarrow.** `verdryx slo` stopped at its first line on a real trace without it.
- **`verdryx-drift` can start.** It ran the console's image with no entrypoint, so the console server refused `/bin/sh` as an argument. Nothing had started it, because no install enables `routines`.
