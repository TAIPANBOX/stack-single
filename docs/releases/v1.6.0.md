# stack-single 1.6.0

A minor release. The box catches up with what the cluster launcher already does: the record is signed and witnessed, vouchryx signs with a key keyryx certifies, a person is named on every approval, the crew can spend through the gateway, and the console's first password is never printed.

## Upgrade first

1. **Run `./install.sh` again from this release.** A box with its own operator files names them as before (`CLIENT_KEYS_FILE=... IDENTITY_MAP_FILE=...`). keyryx restarts once, to read its changed policy.
2. **vouchryx moves to a key keyryx certifies.** A box that set no `VOUCHRYX_SIGNER` moves on this run. The doors stop reading `delegation-public/vouchryx.jwks.json` once and poll vouchryx's key set instead. Write `VOUCHRYX_SIGNER=file` in `.env` first to keep the file key.
3. **Restarting vouchryx now costs two minutes of new tokens.** Its working key lives in memory, so a restart asks keyryx for a new one while the old one is valid, and the new key starts `KEYRYX_PUBLISH_AHEAD` (2 minutes here) later. Tokens already issued keep working. A new one is refused with 503 `no_certified_signing_key` until then, and the installer's checks wait for it.
4. **An approval now needs a console with a passkey.** wardryx checks each decision against the console's public key set, so a console with no enrolled passkey cannot sign a statement, and its approvals are refused with `approver_statement_required`. `WARDRYX_ALLOW_KEY_APPROVALS` is never set.
5. **With `TYPED_RISK_SIGNAL=1`, a tool call the signal does not reach is held for a person.** So is one the classifier marks destructive, external_send or financial at 0.8 or more. The rule is one block in `policy.yaml`, between `# typed-risk-hold` markers, and wardryx restarts to read it.
6. **A fresh install writes the console's password to a file.** The closing report names `console-password` (mode 0600) and the one command that reads it. Delete the file once you have saved the password.

## What changed

- **The record is signed and witnessed.** The seal signs each sealed root through keyryx, with a credential keyryx holds only as a digest, pinned to the one ES384 key of `trailryx-root` (`TRAILRYX_KEYRYX_KID`, taken once at install). The witness reads the records and writes an attestation per root to a volume of their own, `keyryxattest`, which the seal reads and nothing else of the witness's. Invariants 62 and 63.
- **vouchryx signs with a key keyryx certifies, against a root this box pins** (`VOUCHRYX_KEYRYX_ROOT_PIN`, taken once). Invariant 58.
- **Each door accepts a proof for its own addresses.** The gateway and the broker list their service name and the bind this box has, and wardryx takes the union. An agent on the compose network and a client on the host both verify. Invariant 64.
- **A person is named on every approval.** The installer mints the console's approver key once and writes its public key set from the pinned image. A pinned image that cannot print it stops the install. Invariant 61.
- **The crew can spend, and only through the gateway.** `costcrew-run` is a one-shot in profile `crew`, started by a person, off while the console's cadence switch is off, bounded by the smaller of `COSTCREW_CEILING` (default 0) and the console's cadence ceiling. Its client key exists only above 0, and it is on the gateway's static list. Invariant 60.
- **The console's first password is never printed, logged or put on an argument list.** Invariant 59.
- **The checks ask whether a token can be issued.** `install.sh` and `install.sh status` read vouchryx's `/healthz`, so a box that holds no certified key is reported as failing.
