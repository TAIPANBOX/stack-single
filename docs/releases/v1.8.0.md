# stack-single 1.8.0

The MCP broker's tool-call check fails closed: when the gateway cannot judge a call, the broker refuses it instead of letting it through unjudged. A person's passkey approval in the console reaches wardryx on a fresh install, with no fix by hand. The installer no longer downloads the stack-k8s tree unless it builds from source, and the fire drills move to mockryx v0.5.1.

## Upgrade first

1. **A box given its own `CLIENT_KEYS_FILE`, or with static keys added to the broker by hand, needs two more lines and two more map entries before the first run.** The broker's static keys are now also gateway keys of the same id and secret, because the broker asks the gateway about every `tools/call` with the caller's own key. The secrets are the broker's, from `TOKENFUSE_MCP_KEYS` in `.env`:

   ```text
   <the broker's secret for stack-single>:stack-single
   <the broker's secret for drills-broker>:drills-broker
   ```

   ```json
   {"id": "install-check"}, {"id": "drills"}

   {"key_id": "stack-single", "unit": "install-check", "agents": ["agent://local.invalid/install-check"]},
   {"key_id": "drills-broker", "unit": "drills", "agents": ["agent://mockryx.local/*"]}
   ```

   Or run once with `ADD_BROKER_KEY=1`: the installer appends both lines with the broker's secrets, keeping the file's mode, and checks the map first. It never edits your map. Without the lines and the entries the run stops before it installs anything and names each missing id. README, "Client keys and the identity map", has the whole shape.
2. **A box whose keys the installer minted upgrades in one run.** `GATEWAY_CLIENT_KEYS` gains `stack-single` and `drills-broker`, the minted identity map binds each to the one agent it speaks as, and the gateway's static list names both. Every other `.env` value is kept byte for byte. The broker (new setting) and the gateway (new keys, map and static list) are recreated, and the console for item 4; CI's `upgrade` job runs the upgrade on Compose 2.26.1.
3. **A broker `tools/call` with the gateway down is now refused** (`blocked: the taint gate ...`), where 1.7.2 let it through and wrote only a `dependency_failed` line. `TOKENFUSE_MCP_TAINT_FAILMODE` is the literal `closed` in `compose.yaml`, with no switch. A caller that sends no `x-fuse-run-id` to the broker is refused: the check needs the run.
4. **The console is recreated under a pinned user** (`10001:10001`, what its image already runs as). `init-volumes` creates the console's own bus stream, `console.ndjson`, `10001:10001 0640`, and re-owns the console's state volume on every `up`; `approver/` becomes `0:10001 0710` whatever the umask. Neither touches an existing file's content, and a box fixed by hand is brought to the same state.
5. **The installer checks the signature of mockryx v0.5.1 and pulls it** for `mockryx-drill`. Nothing starts it; `docker compose run --rm mockryx-drill` runs the broker drills as before.
6. **Going back to 1.7.2 needs nothing special.** The rollback index stays 1. 1.7.2 leaves `TOKENFUSE_MCP_TAINT_FAILMODE` unset, which tokenfuse reads as open, so the broker's check fails open again. The two extra gateway keys stay in `.env`, unused. `console.ndjson` and `approver/` keep what 1.8.0 gave them.

## What is new

- **The MCP broker's tool-call check fails closed** (#182, CLAUDE.md invariant 75). Before every `tools/call` the broker asks the gateway's `/v1/fuse/check-tool-call`, with the caller's own key for a static caller. A key the gateway does not hold was a 401, which counted as no answer, and with the switch unset no answer let the call through. Now the switch is closed and every static key the broker admits is a gateway key bound to its own agent. See Upgrade, items 1 to 3.
- **The installer fetches the stack-k8s tree only to build from source** (#182, invariant 76). It downloaded the tarball of stack-k8s's main branch on every run, as root, unpinned and unchecked, though only `BUILD_FROM_SOURCE=1` reads it. The fetch is now the first step of that branch. An earlier run's copy stays where it is.
- **mockryx v0.5.1** (#184): a fix for a false Finding in mockryx's reaction-chain and game-day drills, which this box does not run, built with Go 1.27.4. The broker drills and this box's own copy of the tool-hold drill are unchanged.

## Fixed

- **A person's passkey approval reaches wardryx** (#183). Two defects made every approval in the console fail on a live box: the console had no stream on the bus, so it refused to journal the grant, and `approver/` was left to the umask, so the console could not read the approver key. See Upgrade, item 4.

## Evidence

- CI on the release head: every install leg, `browser`, `upgrade` and `upgrade-tool-hold` green. The `typed-risk` leg proves the closed check on an installed box: the installer's check key is judged by the gateway and answered, with the gateway stopped the same call is refused `blocked: the taint gate ...`, and it passes again once the gateway is back. Every leg checks that `console.ndjson` is `10001 0640` and opens for append from inside the console, that the approver key opens from inside it, and that `approver/` is `0:10001 0710` on the host.
- Red first: `scripts/broker-callers-are-gateway-keys.sh` and `scripts/no-unverified-download-outside-build.sh` on the unfixed tree (#182); `docs/evidence/console-bus-and-approver-dir/gates-red-on-f15eb06.txt` (#183).
