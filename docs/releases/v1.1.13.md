# stack-single 1.1.13

A fix for an installer that stopped before it did anything, in every release
from 1.1.9 to 1.1.12. Upgrade by re-running `install.sh`; nothing else changes.

## Fixed

- **`install.sh` stopped at `. ./.env` on every install since 1.1.9.** The
  MCP broker's scope default, `typryx_key=tools:ask|ask_freeform|list_questions`,
  was written to `.env` unquoted, and the installer sources `.env`: the shell
  read `|` as a pipe and ran `ask_freeform` and `list_questions` as commands, so
  the install died with exit 127 before starting a container. The value is
  quoted now. A `.env` written by 1.1.9 to 1.1.12 is repaired in place before
  it is sourced (`repair_env_quoting`: every unquoted value holding a character
  the shell would act on is quoted, anything else is left byte for byte), so a
  box that tried one of those releases can re-run this one. New gate
  `scripts/env-sources-cleanly.sh`, red on 1.1.12, with four teeth cases.

## Measured

On 2026-09-27 on a Debian 13 box (Docker 28):

- 1.1.12 with `WITH_DELEGATION=1`: stopped at `.env` line 45, exit 127.
- This release over that broken `.env`: "quoted 1 value(s)", then every check
  passed; the delegation plane came up (`delegation door: ON`, `./delegation`
  owned by uid 65532, `./delegation-public` for the gateway); a delegated call
  was accepted, the subject revoked and refused 6.7 s later at the default 12 s
  poll; a re-run passed every check with the signing key and the revocation
  kept.
- A fresh default install into an empty directory: every check passed in 41 s,
  no vouchryx, no delegation variable on the gateway.

## Not in this release, said plainly

- Nothing ran install.sh on a real box between 1.1.9 and this run, which is how
  the defect shipped four times. The new gate checks the file statically and the
  repair on a fixture; it does not run the installer.
