# stack-single 1.4.4

A patch that moves six images to newer releases: TokenFuse 1.20.1 to 1.20.2, the console 1.7.0 to 1.7.3, the caddy and tunnel images to 1.7.3, and the trailryx-node record seal from 1.4.0 to 1.5.0. The console and the tunnel are built on Go 1.27.3, which fixes GO-2026-6809 in `crypto/x509`.

## Upgrade first

1. **Run `./install.sh` again from this release.** A box with its own operator files names them as before (`CLIENT_KEYS_FILE=... IDENTITY_MAP_FILE=...`). The installer checks each new image's signature, pulls it by digest and recreates the services whose image changed. Nothing else needs to be set.
2. **TokenFuse 1.20.2 prices `gpt-6.1-terra` at its own row.** Until now the model had no row, so each call was estimated and recorded at the fallback price of 15 USD (input) and 75 USD (output) per million tokens. It is now priced at OpenAI's Standard list, about a fifteenth of that. Budgets for that model burn that much more slowly, and the `x-fuse-price` response header no longer says `fallback` for it. Nothing to configure. A row for the model in `TOKENFUSE_PRICE_BOOK` still wins over the built-in row; this launcher does not set that variable.
3. **trailryx 1.5.0 changes nothing on a stock install.** The seal signs only when `TRAILRYX_SIGNER` is set, and this launcher does not set it, so the record seal runs as before. A node with `TRAILRYX_SIGNER=keyryx` and no `TRAILRYX_KEYRYX_KID` now refuses to start. That variable is the RFC 7638 thumbprint, 43 base64url characters, of the Keyryx key the seal signs under. Each Keyryx signature is also checked before it is stored: one that does not verify leaves its root queued, and a pack built while the root is queued says it is unsigned. This applies only to a box whose operator has set the Keyryx signer by hand, since this launcher does not wire it.
4. **The console and the tunnel image have no operator-visible change recorded for this release.** Their change is the Go 1.27.3 base.

The image-verify fixtures, the teeth cases that plant faults next to these pins, and the README and CLAUDE.md lines that name the console and TokenFuse versions follow them.

What the upstream releases changed:

- **TokenFuse 1.20.2** (its pull requests #484 to #489): `zstd-sys` moves to 2.1.2 for RUSTSEC-2026-0410. RUSTSEC-2026-0391 and RUSTSEC-2026-0403 stay as a recorded, temporary exception in TokenFuse's own audit, and its audit script fails once the exit condition is met: DataFusion 56, or any release that takes parquet and arrow-ipc 60.
- **trailryx-node 1.5.0** (its pull requests #112 and #113): the Keyryx signer signs under one pinned key and checks each signature. No record, journal, pack or wire format changes, and the frozen section of `COMPATIBILITY.md` is unchanged.

## Checked locally

- Each new digest was read from the registry with `docker buildx imagetools inspect` on 2026-10-28. Each index digest equals the value pinned above.
- Each new image has its cosign signature tag (`sha256-<digest>.sig`) in the registry. The signature identity is checked by the installer's cosign run, which the CI install job exercises.
- The provenance of genaryx-console v1.7.3 and stack-wg v1.7.3 names `golang:1.27.3-alpine`.
- `git grep` finds no old tag or digest outside `docs/releases/`.
- 48 of the 53 gates in `.github/workflows/gates.yml` pass on this Mac. Five need tools it does not have running: shellcheck (`shell-lint`) and a Docker daemon (`broker-blocks-raw-secrets`, `identity-files-are-checked`, `metered-doors-require-keys`, `openai-door`). CI runs them.

## Not measured

- No box was installed or upgraded with these pins. The forge upgrade follows separately.
- cosign was not run on the new images here, since cosign is not installed on this machine.
- The console 1.7.x and the caddy and tunnel 1.7.3 release notes were not read beyond the provenance check.
- TokenFuse 1.20.2 was not run against a live OpenAI response. Its `gpt-6.1-terra` price is proven by unit tests and the regenerated contract, not by a recorded call.
- trailryx 1.5.0 was not run against a live Keyryx. Its tests use a stub.
- No stack-single release is cut by this change. The tag goes on the merge commit when it is cut.
