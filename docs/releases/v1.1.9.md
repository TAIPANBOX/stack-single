# stack-single 1.1.9

The typed-answer plane arrives as an opt-in, fronted by TokenFuse's own MCP
broker, and TokenFuse moves to 1.3.0.

## What changed

- **typryx as an opt-in typed-answer plane (#70, #72).** `WITH_TYPED=1
  ./install.sh` pulls and starts `typryx` (`ghcr.io/taipanbox/typryx:v0.2.0`,
  backend `stub`, no outbound call) and `tokenfuse-mcp-broker`, the same
  TokenFuse image on its `mcp-broker` subcommand. The broker is published on
  `${GATEWAY_BIND:-127.0.0.1}:4200`, so it is closed by default exactly like
  the gateway; typryx itself has no host port. `install.sh` generates the
  broker's client key and hands typryx's key to the broker's vault, scoped to
  typryx's three tools, so an agent never holds it. typryx's journal is on
  the shared `events` volume, where heraldyx reads it; its ledger stays on
  its own volume. Without `WITH_TYPED` nothing of this starts.
- **TokenFuse 1.3.0 (gateway, `focus-export`, the MCP broker and the control
  plane; they were 1.1.1).** 1.2.0 names a gateway's site by the Cloud key it
  pushes with and adds `GET /v1/gateways`; 1.3.0 makes an idle gateway send
  its Cloud a heartbeat every 30 s (`TOKENFUSE_CLOUD_HEARTBEAT_SECONDS`, `0`
  turns it off). On one box the Cloud is local, so this costs one small
  request every 30 s on the compose network and keeps the box's own last
  push fresh. Nothing frozen in TokenFuse's 1.0 surface moved.

## Measured

- The broker and typryx on Docker Desktop, a throwaway compose project
  (#72): the broker refused a call with no client key or the wrong one
  (401), typryx's `typed_answer` line landed on the shared `events` volume,
  and neither secret appeared in any container's log.
- The same wiring on a cluster (stack-k8s, typryx `v0.2.0`): an `ask`
  through the broker with typryx's key present only as a vault handle was
  answered.
- TokenFuse 1.3.0's heartbeat on 2026-09-27, a GCP hub and a site at home,
  the site idle: without it the site's last push aged from 34 s to 286 s in
  four minutes; with it, one push about every 31 s.

## Upgrade

Re-run `install.sh` on the box. The gateway's and the control plane's images
are pulled; `.env` is left as it is, and the new broker variables are added
to it only if missing. Add `WITH_TYPED=1` to also start the typed plane.

## Not in this release, said plainly

- A full `install.sh` run with this pinned set was not made on a fresh box,
  with or without `WITH_TYPED=1`.
- The TokenFuse 1.3.0 image was not run in this launcher. The heartbeat was
  measured on a cluster with images built from the pull request.
- record-seal does not seal typryx's events: the pinned record plane refuses
  their four types by name, as it does other types it does not map.
